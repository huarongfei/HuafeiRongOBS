## 1. 摘要与目标/非目标

### 1.1 一句话定位
**一台 Windows 机器 = 演出/会议/展厅/多机位导播的"多屏 + 多推流 + 录制"一体机。**

### 1.2 目标
- 多画布：同一进程同时运行 5~8 路输出画面（设计目标；**上游 32.2.2 已提供 obs_canvas 早期 API，我们在此之上做产品化**）；
- 克隆：任意画布一键克隆到多块真实屏、多路推流与一路主录制；克隆带独立裁切/缩放/安全区；
- 混合工作流：默认"主节目画布（PGM）"，个别屏可脱离 PGM 独立接管；
- 2~3 路并发推流（抖音/B站/视频号/YT/Twitch/RTMP 自定义）+ SRT/NDI 输出；
- 每路输出目标独立选听混音（现场与直播不同声）；
- HuafeirongOBS Console 导播控制台（预览墙/场景坞/素材坞/切换台/多屏布局/三种模式）；
- 内置 LibreOffice PPT 讲者模式；切换台/一键回放/倒计时/健康监测/API 扩展；
- 简体中文默认 + 英文可切；设置三层分组 + 首启向导。
- 文档与里程碑面向"能看懂一点 C++"的开发者：可读、可验证、增量推进。

### 1.3 非目标（v1.0 不做）
PPT 新建/编辑；平板/网页遥控端；多画布各自录制文件（只录 PGM）；手机无线投屏采集；
NDI 输入（仅输出侧）；AI 美颜/抠像；OSC/MIDI 实装；macOS/Linux。

## 2. 背景
原版 OBS（≤31）单实例只有一路 Program：一路最终画面进编码/推流/监视；Preview 只是"下一版"；
来源实例绑定单一渲染链；音频一套混音；UI 面向单机位个人直播。
**重要变化（32.x）**：上游开始引入 Canvas API（obs_canvas_t，作者 D. Sädtler/Twitch，2025 起，
标记 unstable、持续演进）。**我们没有从零改造单节目内核的必要——路线转为：搭上上游多画布列车，
补全"渲染调度/输出绑定/音频路由/Console UI"，并针对现场演出场景做产品化。**
（上游 canvas 现状盘点见 §5.3；与官方 UI 的差异正是我们的差异化空间。）

## 3. 需求规格（最终）
### 3.1 用例速览
**U1 会议/教堂**：摄像头×1 + PPT×1 → PGM（主持人画面/幻灯可切）→ 克隆到主投影 + 直播(B站) + 录制。
**U2 演出**：机位×2(USB+HDMI采集卡) + PPT + 素材 → PGM 克隆 LED 主屏；候场屏独立画布（倒计时/场务）；
直播(视频号/抖音竖屏独立画布)。
**U3 展厅/LED**：多块屏独立画布循环素材（按需档），一块屏跟 PGM 播活动直播。
**U4 多机位导播**：切播员切机位/PPT（Cut/Auto）；素材员备料（同机分工、区域锁）。

### 3.2 功能需求 FR（同 v1.0，关键条目标注与上游 canvas 的关系）
| 域 | 编号 | 需求 | 上游基线 |
|---|---|---|---|
| 画布 | FR-C1 | 画布 CRUD；每画布独立场景集/当前场景/尺寸/渲染纹理 | ✅ 已具备（obs_canvas/scene/video API） |
| 画布 | FR-C2 | PGM 标记与默认存在 | ✅ 主画布 MAIN 天然存在 |
| 输出 | FR-O1 | Sink=屏独占全屏/推流/录制/SRT/NDI，绑定画布 | ⚠️ 部分：canvas video 可喂编码器，绑定模型自研 |
| 输出 | FR-O2 | 克隆共享纹理；独立裁切/缩放/安全区/LUT | ⚠️ 自研（render canvas texture 已提供） |
| 输出 | FR-O3 | 3+ 真实屏（监视器枚举+全屏独占）；布局保存 | ❌ 自研（OBS 现有全屏投影可扩展） |
| 输出 | FR-O4 | 5~8 路画布；分级降帧 | ⚠️ 渲染调度/活跃度档位自研（上游 canvas fps 用全局帧率） |
| 切换 | FR-S1 | 每画布 Cut/Auto/Fade/白黑场/滑入/Stinger | ✅ 转场体系沿用，需改为"按画布"作用域 |
| 推流 | FR-P1 | 每画布 1~N 路推流（RTMP/SRT） | ⚠️ 现推流绑全局输出，需按 canvas video 重构绑定 |
| 推流 | FR-P2 | 健康监测（码率/丢帧/断流自检/重连/告警） | ❌ 自研（可参考社区脚本思路，原生实现） |
| 录制 | FR-R1 | 录制一路 PGM（MKV，可选转 MP4） | ⚠️ 输出重构后绑定 PGM 即可 |
| 音频 | FR-A1 | 输出目标级音频路由（混音组+增益+延迟） | ⚠️ canvas 有 MIX_AUDIO（多画布混入总输出）；"按 Sink 选混音"需扩展 |
| PPT | FR-PPT1/2 | pptx 上屏 + 讲者视图 + 翻页笔 | ❌ 自研 ppt-bridge（§9） |
| UI | FR-U1..U4 | Console：预览墙/场景坞/素材坞/切换台/多屏布局/三模式/设置分层/中英 | ⚠️ 前端仅有 canvas 存取壳（OBSCanvas.*），无 GUI 入口 → 自研为主 |

### 3.3 性能与规模承诺（笔记本务实档，同 v1.0）
全帧率合成 2×1080p60；推流 1 路 1080p 稳定（2~3 路需降档/换机）；其余画布按需/预览/暂停自动分级；
4K 架构预留（上游 canvas reset_video 支持任意 base 分辨率——但注意 fps 为全局，见 §6.3）。

## 4. 术语与概念模型
- **画布 Canvas**：独立合成空间。上游 obs_canvas_t = 场景集合 + 视频配置 + 渲染纹理（MAIN 常驻）。
- **PGM**：默认主节目画布（上游主画布/MAIN flag）。
- **Sink 输出目标**：屏克隆窗/推流/录制/SRT/NDI；Sink 绑定画布 = 跟随（克隆）；改绑 = 独立接管 → 克隆/独立/混合统一表达。
- **来源扇出 Fan-out**：同一采集源进多画布时"渲染一次、共享纹理、扇出"（上游 source 与 canvas 的关系需 M1 核实：obs_source_get_canvas 已存在）。
- **音频路由**：混音组 → Sink（§7）。
- **活跃度分级**：实时/按需/预览/暂停（我们加入的画布 GPU 调度策略）。

### 5.3 上游 32.2.2 Canvas 基线盘点（M0 源码核实结论，2026 现场查验）
- **API 面**（libobs/obs.h 2604~2694 + obs-canvas.c 462 行）：
  obs_get_main_canvas / obs_canvas_create(_private) / remove / name+uuid / flags /
  save+load / refcount+weak / channel set/get / 画布内场景 create/remove/move/enum /
  reset_video(任意 base 分辨率，fps 用全局) / has_video / get_video(video_t) / get_video_info / obs_canvas_render。
- **标志与预设**：MAIN / ACTIVATE / MIX_AUDIO / SCENE_REF / EPHEMERAL；
  PROGRAM = ACTIVATE|MIX_AUDIO|SCENE_REF；PREVIEW = EPHEMERAL；DEVICE = ACTIVATE|EPHEMERAL。
- **渲染**：obs.c 已有主画布纹理渲染内部实现（obs_render_canvas_texture*）；obs_canvas_render 在 obs-canvas.c:589。
  多画布逐帧渲染与分档调度**上游未接**（obs-video 主循环无 canvas 枚举渲染）→ 我们的核心增量。
- **前端**：frontend/utility/OBSCanvas.{cpp,hpp}（RAII 壳+Save/Load）+ OBSBasic_Canvases.cpp
  （Add/Remove/Clear + OBS_FRONTEND_EVENT_CANVAS_*）；profile 可持久化多画布；
  **GUI 无创建/管理入口**（无 AddCanvas 调用方）→ UI 由我们重建。
- **音频**：MIX_AUDIO 表明"多画布音频混入总输出"的意图已预留；**按 Sink 选混音的路由模型不存在**（§7 自研）。
- **源码锚点**：libobs/obs-canvas.c、libobs/obs.c（~2170/2224/2234）、libobs/obs.h、frontend/utility/OBSCanvas.*、
  frontend/widgets/OBSBasic_Canvases.cpp、docs/sphinx/reference-canvases.rst（302 行，含全部函数说明）。

## 6. 核心设计：在 obs_canvas 之上构建多画布直播系统
### 6.1 工作分块（替代旧"从零改造"路线）
1. **M1 spike（2 周）**：读 obs-canvas.c/obs.c 渲染路径；跑通"额外创建画布→按帧渲染到纹理→窗口显示"最小验证；确认 source 跨画布行为（ACTIVATE/SCENE_REF 与扇出）；写 spike 报告进 ADR。
2. **画布调度器**：统一帧循环中按活跃度分档调度各画布 obs_canvas_render；非活跃画布暂停。
3. **Sink 层**：绑定模型（Sink.bind(canvas)）、克隆（同纹理多次取样：缩放/裁切/安全区/LUT）、屏幕枚举与全屏独占、布局持久化。
4. **音频出局路由**（§7）；**编码/推流/录制改绑画布 video**（沿用现有 encoder 管线）。
5. **Console UI**（§8）。

### 6.2 已知约束与对策
| 上游约束 | 对策 |
|---|---|
| canvas fps = 全局渲染帧率 | 活跃度档用"整帧跳过/内容触发"实现降帧；高配机再评估每画布独立线程 |
| canvas API unstable | 锁定 32.2.2 基线，上游合入策略（§14 风险） |
| source↔canvas 绑定细节 | M1 spike 实测后定扇出方案 |
| 前端无画布 GUI | Console 自研，含 5~8 路缩略墙 |

## 7. 核心设计：音频路由
- 沿用上游音频引擎（采集/滤波/总线）；新增 **Sink 出局路由表**：Sink → {混音组, 增益, 延迟校正}。
- 上游 canvas MIX_AUDIO 关系在 M1 核实（多画布是否各自混入总输出）后，确认路由落点
  （可能：画布级选择参与输出的音频通道 + Sink 级选择画布/组，双级路由）。
- 默认：PGM 的 Sink 听 Main；直播可绑"Main+解说"自定义组。
- 声卡策略（WASAPI 独占/监听/ASIO）在 M3 spec 细化。

## 8. UI：HuafeirongOBS Console
（布局/三模式/设置分层/素材坞/i18n 设计同 v1.0 §8，摘要如下）
- 中央监视墙（画布与 Sink 实时网格，点开放大/拖到任意屏）；左侧场景坞（每画布标签+分组）与素材坞；
  右侧输出与推流面板（Sink 绑定下拉/状态/码率/健康）；底部切换台（目标画布→场景/机位/PPT 页；Cut/Auto；回放/倒计时）。
- 模式：单人（精简）/ 导演（默认预览墙+切换台）/ 同机协作（区域锁，键盘事件路由）。
- 设置基础/进阶/专家三层 + 首启用途向导（会议/演出/展厅/直播 → 生成画布布局与推流预设）。
- 语言：默认简体中文 + 英文可切（全部文案走 Qt tr()，M4 执行）。
- 注意：沿用 OBS dock 体系的成熟窗口管理，在其上加"多屏布局引擎"，控制工程量。

## 9. 内置媒体输出：PPT 讲者模式
（同 v1.0 §9：pptx 上屏 + 讲者视图（备注/当前页/下页预览，独立窗口拖任意屏）+ 键盘/翻页笔；

## 11. 性能预算与硬件
- 开发验证机：3500U/Vega8/30GB。务实档：2×1080p60 全帧率 + 1 路推流；其余画布分级。
- 实测点：多画布纹理扇出带宽；AMF vs 合成争用；x264 档位。
- 发布档建议：i5-12400/R5-5600+；独显 RTX4060/RX7600 级；3~4 路视频输出；≥32GB。
- 每新增 1080p60 画布 ≈ 独显 5~8% GPU（M1 后校准）。
