# 晨间验收清单（M1 E1/E2）

## 环境
- 运行：D:\HuafeirongOBS\obs-src\build_x64\rundir\RelWithDebInfo\bin\64bit\obs64.exe
- 建议：命令行加 --portable（配置写在运行目录旁，不污染用户目录）。手动双击即可（已确认手动启动正常）。

## 验收步骤
1. 启动 OBS 32.2.2（改造版）。顶部菜单栏应出现 **HFR(M1)**。
2. 菜单 HFR(M1) → **E1: 第二画布窗口（克隆演示）**
   - 期望：弹出 "HFR-E1 Canvas (clone demo)" 窗口，内容与主预览一致（克隆语义）；Esc 关闭。
3. 菜单 HFR(M1) → **E2: 第二画布窗口（独立色块）**
   - 期望：弹出 "HFR-E2 Canvas (independent demo)" 整窗亮青色（该画布拥有独立场景与色块源）。
4. （可选自动演示）设置环境变量 HFR_E1_AUTO=1 后启动，4 秒后自动开 E1 窗口。
5. 观察日志（config\obs-studio\logs 下最新 .txt）：应含
   - "[HFR] obsinit: registering HFR(M1) menu..."
   - "[HFR-E1] open: clone canvas..." / "[HFR-E2] open: independent canvas..."
   - 窗口创建成功标记。
6. 关闭窗口/退出 OBS 不应崩溃；再次启动正常。

## 已知限制 / 观察点（决定 M2 设计）
- 两个演示画布 flags = ACTIVATE|SCENE_REF（无 MIX_AUDIO → 无音频混入，避免重复出声）。
- 画布 base 分辨率 960x540（独立于主画布）；帧率用全局（上游约束）。
- 窗口显示依赖 obs_display 与 mix->texture_rendered（每帧由 output_frames 渲染）。
- 若 E1/E2 运行崩溃或黑屏：请记录 obs 日志尾部 + 现象 → 决定是否等待上游 canvas 成熟 / 或走
  "create 需 graphics 线程/视频停止期" 的改造路线（候选：渲染回调内懒创建、或 M2 spike 时用 obs_queue_task 类机制）。
